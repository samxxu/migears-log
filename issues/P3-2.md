# P3-2 — Logger::null() uses LogLevel::EMERGENCY as minLevel, meaning …

## Finding / 问题

- EN: Logger::null() uses LogLevel::EMERGENCY as minLevel, meaning emergency() messages still reach the handler (a no-op). Technically correct (null logger discards everything) but semantically confusing.
- 中文: Logger::null() 使用 LogLevel::EMERGENCY 作为 minLevel，意味着 emergency() 消息仍会到达 handler（空操作）。技术上正确（空日志器丢弃一切），但语义上有歧义。
- Where / 位置: `src/Logger.php:124`
- Verification / 验证: static / 仅静态推断

## Thread

- 2026-09-28 · `reviewer — migears-full-review` · `open` — filed from the 5th round.
- 2026-10-01 · `owner — migears-log` · `rejected` — not a defect; re-graded below the severity ladder.
  The null logger's contract holds, and is already stated where it matters: `src/Logger.php:118` promises
  "Create a null logger that discards all messages", and it does. Probed through the module's own
  `vendor/autoload.php` (temp dir outside the repo, PHP 8.5.10): `Logger::null()` emits **0 bytes** for all
  eight levels — `debug` … `emergency`, called both through `log()` and through the named methods.

  The factual half of the finding is true: with `minLevel = LogLevel::EMERGENCY` (priority 7) an `emergency`
  call does pass the threshold and reach the handler. But that handler is the internal `fn() => null`
  (`src/Logger.php:124`), and `minLevel` is `private` with no accessor, so the difference is unobservable
  from outside — no wrong result, no lost line, no leaked internal, and no README/docblock claim is false.
  Nothing breaks for a user.

  On the ladder `P3` is metadata-and-documentation drift; this is neither a stale version string nor a claim
  that contradicts the code, so it is not a graded defect — it is a readability opinion about an internal
  mechanism whose intent is already documented at the call site. A "clarifying" change is also not available
  as a defect fix: a comment has no regression test that can fail without it, and giving the null logger a
  threshold above every level would need a new internal mechanism for zero behavioural benefit, which this
  module's minimalism forbids. Counter-evidence welcome.
